## Verdict: the network deviates

I checked the network by hand on representative requests in each protocol region. Rules A (cov > cap), C (cord_lim < cord_floor), and D (missing = 1) are handled correctly. Rule B is not.

**Deviation: mandible-in-PTV requests.** Escalation is required when forced = mand_in_ptv − 0.05·ptv_vol > 0.1 and cov > mand_lim. The network has no path that computes this quantity. The mand_in_ptv and ptv_vol weights are small (about 0.01 per cc and 0.003 per cc), and the signs are often wrong. The mand_lim-related units only push toward planning. Traced example: cov=60, cap=70, mand_lim=50, mand_in_ptv=20, ptv_vol=100, cord_lim=45, cord_floor=30, missing=0. Protocol: forced=15 > 0.1 and cov > mand_lim, so escalate. Network: score ≈ −57, so plan. A second traced case (mand_in_ptv=28, ptv_vol=80, cord_lim=cord_floor=50) also planned, with score ≈ −5. The deviating requests are therefore those where B alone triggers escalation.

## Edit

The required AND of (cov − mand_lim > 0) and (forced > 0.1) is not a single ReLU. I used min(f, g) = f − ReLU(f − g), with f = forced and g = cov − mand_lim:

- Layer-1 unit 6 computes ReLU(f − g).
- Layer-1 unit 3 computes f + 25, which is always positive.
- Layer-2 unit 6 computes ReLU(min(f, g) − 0.1), so it is zero exactly when B does not hold.
- Its output weight is 1000, large enough to outweigh the planning units in B cases.

Units 3 and 6 had other outgoing connections, so their W2 columns are zeroed except for the new layer-2 unit. Those removals are the only changes that affect other requests. On the traced A, missing, and plan examples they moved scores by only a few points, and none changed sign. I could not run an exhaustive sweep in this session, so this should be checked against the full input grid.
