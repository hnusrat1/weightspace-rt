The score is the total amount by which a request breaks the protocol. Each rule becomes a term that is exactly 0 when the rule does not hold and positive when it does. Adding the terms gives "at least one rule holds." A bias of −0.05 places the cut just above zero.

| Rule | Term (raw units) |
|---|---|
| A | ReLU(cov − cap) |
| B | ReLU(min(f, d)), where f = forced − 0.1 and d = cov − mand_lim |
| C | ReLU(cord_floor − cord_lim) |
| D | missing |

**score = A + B + C + D − 0.05**

**Rule B needs both conditions**, so it uses the smaller of the two margins, which is positive only when both are. Two ReLU layers compute it as ReLU(min(f, d)) = ReLU(ReLU(f) − ReLU(f − d)):
- **f ≤ 0:** ReLU(f) = 0, so the result is 0. This is correct because min(f, d) ≤ f ≤ 0.
- **0 < f ≤ d:** ReLU(f − d) = 0, so the result is f, which equals min(f, d).
- **f > 0 and f > d:** the result is ReLU(f − (f − d)) = ReLU(d), which equals ReLU(min(f, d)).

**Undoing the scaling** (raw = center + scale·x):
- cov − cap = 10x0 − 10x1
- cord_floor − cord_lim = 10x6 − 10x5
- forced = 10x3 − 5x4
- cov − mand_lim = 10x0 − 10x2

**Layer 1** (units 5–15 are unused and all zero):

| Unit | Pre-activation | Bias | Output |
|---|---|---|---|
| 0 | 10x0 − 10x1 | 0 | ReLU(cov − cap) |
| 1 | −10x5 + 10x6 | 0 | ReLU(cord_floor − cord_lim) |
| 2 | x7 | 0 | missing |
| 3 | 10x3 − 5x4 | −0.1 | ReLU(f) |
| 4 | −10x0 + 10x2 + 10x3 − 5x4 | −0.1 | ReLU(f − d) |

**Layer 2** (units 4–15 are unused):
- Units 0–2 copy layer-1 units 0–2, which are already non-negative.
- Unit 3 = ReLU(h1[3] − h1[4]), which is the rule B term.

**Output:** weight 1 on layer-2 units 0–3, bias −0.05.

**Why it follows the protocol**
- **No rule holds.** Then cov ≤ cap, cord_floor ≤ cord_lim, missing = 0, and f ≤ 0 or d ≤ 0. Every term is exactly 0, so the score is −0.05 and the request goes to planning. This holds right up to each threshold, so a compliant request is never escalated.
- **Some rule holds by at least 0.3 Gy/cc.** That term is at least 0.3, or 1 for a missing structure. The other terms are never negative, so the score is at least 0.25 and the request is escalated.
- **The only possible disagreement** is a request whose violations total 0.05 Gy/cc or less. It goes to planning, which is well inside the 0.3 tolerance.

The weights compute these formulas exactly rather than approximating them, so the behaviour also holds outside the listed ranges.

**Worked example:** cov 70, cap 72, mand_lim 65, mand_in_ptv 15 cc, ptv_vol 150 cc, so forced = 7.5 cc. The cord goal is met and no structure is missing.
- Unit 3 = 7.4 and unit 4 = ReLU(7.4 − 5) = 2.4.
- The B term is 7.4 − 2.4 = 5.0, which equals min(7.4, 5).
- The score is 4.95, so the request is escalated.

If mand_lim is 72 instead, d = −2 and unit 4 = 9.4. The B term is ReLU(−2) = 0, the score is −0.05, and the request goes to planning.

**Optional variant:** as given, borderline cases go to planning. To send them to a person instead, set b1[0] and b1[1] to 0.1 and b1[3] to 0. Then every real violation is escalated. A compliant request may also be escalated, but only if it is within 0.1 Gy/cc of a threshold.
